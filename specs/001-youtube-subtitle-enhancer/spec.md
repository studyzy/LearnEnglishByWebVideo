# 功能规范: YouTube智能字幕增强器

**功能分支**: `001-youtube-subtitle-enhancer`
**创建时间**: 2026-01-19
**状态**: 草稿
**输入**: 用户描述: "我想写一个Chrome的插件，针对YouTube网站，打开一个视频播放时，这个插件能够下载整个视频的字幕内容，然后把字幕中的英文单词根据我预设的我的英语水平找出不认识的单词，然后把不认识的单词旁边显示出中文。所以看视频时看到的就是中英文混合的字幕。"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 基础字幕增强显示 (优先级: P1)

作为英语学习者，当我在YouTube上观看英文视频时，我希望看到经过增强的字幕，其中我不认识的单词旁边自动显示基于上下文的中文解释，这样我可以在不暂停视频的情况下理解内容并学习新词汇。

**优先级原因**: 这是核心价值主张，提供最直接的学习体验改善。没有这个功能，插件就失去了存在意义。

**独立测试**: 用户可以安装插件、打开任何带英文字幕的YouTube视频，立即看到增强后的混合字幕显示。可以完全测试并交付"边看边学"的核心价值。

**验收场景**: 

1. **给定** 用户已安装插件并配置了LLM API及英语水平为"中级"，**当** 用户打开一个带英文字幕的YouTube视频时，**那么** 字幕区域自动显示增强字幕，中级以上难度的单词旁边显示基于字幕上下文的简短中文解释
2. **给定** 视频正在播放且字幕已增强，**当** 字幕内容随着视频进度更新时，**那么** 新显示的字幕同样包含生词的上下文解释，解释简短且准确
3. **给定** 用户正在观看增强字幕，**当** 字幕中包含专有名词、俚语或习语时，**那么** LLM会基于上下文提供恰当的中文解释，而非简单的词典翻译
4. **给定** 视频有多语言字幕可选，**当** 用户选择了英文字幕，**那么** 插件只对英文字幕进行增强处理，不干扰其他语言字幕

---

### 用户故事 2 - 英语水平与LLM配置 (优先级: P2)

作为不同英语水平的学习者，我希望能够设置我的英语水平档次和配置LLM API，这样插件可以只标注我不认识的单词并提供智能的上下文解释，避免显示过多或过少的翻译。

**优先级原因**: 个性化设置直接影响用户体验质量。初级学习者和高级学习者看到相同标注会降低工具的实用性。这是P1功能的重要补充，但不影响核心演示。

**独立测试**: 用户可以在插件设置页面选择不同的英语水平（初级/中级/高级），然后观察同一视频中标注单词数量的变化。可以独立验证个性化配置功能。

**验收场景**: 

1. **给定** 用户首次安装插件，**当** 用户点击插件图标打开设置面板时，**那么** 显示配置向导，包含LLM API配置（API密钥、服务提供商选择）和英语水平选择界面
2. **给定** 用户在设置中配置LLM API，**当** 用户输入API密钥并选择服务提供商（如OpenAI、Claude等）时，**那么** 插件验证API密钥的有效性并保存配置
3. **给定** 用户在设置中，**当** 用户选择"初级"水平时，**那么** 插件标记大约3000个常用词以外的所有单词为生词
4. **给定** 用户在设置中，**当** 用户选择"中级"水平时，**那么** 插件标记大约6000个常用词以外的单词为生词
5. **给定** 用户在设置中，**当** 用户选择"高级"水平时，**那么** 插件只标记学术词汇、专业术语和高级表达
6. **给定** 用户已经在观看增强字幕的视频，**当** 用户在设置中切换英语水平时，**那么** 当前视频的字幕立即更新以反映新的标注策略

---

### 用户故事 3 - 智能词汇管理 (优先级: P3)

作为有特殊学习需求的用户，我希望能够手动管理我已掌握的单词，并且系统能够智能识别词形变化，这样插件的标注更符合我的实际情况，不会因为时态、单复数等变形而重复标注我已经认识的词。

**优先级原因**: 这是高级个性化功能，进一步提升用户体验。词形智能识别可以显著减少冗余标注，提升学习效率。

**独立测试**: 用户可以在设置中管理"已掌握词汇表"和"重点关注词汇表"，添加词根后验证其各种变形在字幕中的标注行为是否符合预期。

**验收场景**: 

1. **给定** 用户在设置页面，**当** 用户点击"已掌握词汇"管理按钮时，**那么** 显示词汇列表界面，用户可以添加、删除、搜索单词
2. **给定** 用户添加了单词"run"到"已掌握词汇"列表，**当** 字幕中出现"run"、"runs"、"running"、"ran"等任何变形时，**那么** 这些变形都不再显示中文解释
3. **给定** 用户添加了单词"study"到"已掌握词汇"列表，**当** 字幕中出现"study"、"studies"、"studied"、"studying"时，**那么** 所有这些形式都被视为已掌握
4. **给定** 用户创建了"重点关注词汇"列表，**当** 列表中的单词出现在字幕中时，**那么** 这些单词使用特殊高亮显示（如不同颜色），并显示中文解释
5. **给定** 插件识别词形变化，**当** 遇到不规则动词或特殊变形时，**那么** 系统能够正确识别并关联到词根（如"went"关联到"go"）
6. **给定** 用户在词汇管理页面，**当** 用户点击"导出词汇"按钮时，**那么** 系统生成CSV文件（包含已掌握词汇和重点关注词汇），自动下载到本地
7. **给定** 用户有外部CSV格式的词汇文件，**当** 用户点击"导入词汇"并选择CSV文件时，**那么** 系统读取CSV内容并覆盖当前的词汇表，显示导入成功提示（包含导入的词汇数量）
8. **给定** 用户导入的CSV文件格式不正确，**当** 用户尝试导入时，**那么** 系统显示清晰的错误提示，说明正确的CSV格式要求，并且不修改现有词汇表

### 用户故事 4 - 交互式熟词标记 (优先级: P4)

作为正在观看视频的学习者，当我看到字幕中某个带中文解释的生词时，如果我发现自己其实认识这个词，我希望能够快速标记它为熟词，并立即移除当前字幕中的中文解释，这样可以动态优化我的学习体验。

**优先级原因**: 这是即时反馈功能，提升用户体验的流畅性。允许用户在观看过程中快速调整词汇表，比切换到设置页面更高效。

**独立测试**: 用户可以在观看带增强字幕的视频时，通过暂停并点击标记按钮来测试熟词标记功能，验证标记后的即时效果和持久化存储。

**验收场景**: 

1. **给定** 用户正在观看增强字幕的视频，**当** 用户暂停视频时，**那么** 每个带中文解释的生词右上角显示一个小叉图标（×标记）
2. **给定** 字幕暂停且显示小叉图标，**当** 用户点击某个生词的小叉图标时，**那么** 该词的中文解释立即从当前字幕中移除，该词添加到"已掌握词汇"列表
3. **给定** 用户标记了某个词为熟词，**当** 用户恢复播放视频且后续字幕出现该词或其变形时，**那么** 这些词不再显示中文解释
4. **给定** 用户标记了多个词为熟词，**当** 用户打开设置页面的"已掌握词汇"列表时，**那么** 这些通过交互标记的词都出现在列表中
5. **给定** 字幕中有多个生词，**当** 用户暂停后点击其中一些词的小叉图标时，**那么** 只有被点击的词的解释被移除，其他生词的解释保持显示

### 边界情况

- **无字幕视频**: 当YouTube视频没有提供英文字幕时，插件显示友好提示"此视频暂无英文字幕，无法提供增强功能"，不影响正常观看
- **自动生成字幕**: 当视频只有自动生成的字幕（准确度较低）时，插件显示警告图标提示用户字幕可能不准确，但仍提供翻译功能
- **多语言混合字幕**: 当字幕中混合了中文和英文时，插件智能识别英文部分进行处理，不对中文部分添加标注
- **网络错误**: 当LLM API请求失败时，插件显示错误提示图标，并使用缓存的翻译结果（如果有），避免完全无法使用
- **快速切换视频**: 当用户快速切换不同视频时，插件取消正在进行的字幕下载和处理任务，避免资源浪费
- **超长字幕**: 当某条字幕包含大量生词时（如超过10个），插件智能选择最重要的词汇进行翻译标注，避免字幕区域过于拥挤
- **特殊字符和表情**: 字幕中的emoji、特殊符号、URL链接等不进行翻译处理
- **播放速度调整**: 当用户调整视频播放速度时，字幕同步和翻译显示不受影响
- **全屏模式**: 在全屏播放模式下，增强字幕正常显示，位置和样式适配全屏界面
- **CSV文件过大**: 当用户尝试导入超过10000个单词的CSV文件时，插件警告用户文件过大可能影响性能，询问是否继续导入
- **CSV格式错误**: 当导入的CSV文件不符合规定格式（缺少必需列、编码错误等）时，显示具体错误信息和正确格式示例，不修改现有数据
- **词汇表为空**: 当用户尝试导出空的词汇表时，提示用户"当前没有词汇可导出"，但仍允许导出空CSV文件
- **重复导入**: 当用户多次导入词汇时，新导入的数据完全覆盖旧数据（提前警告用户），而非追加合并

## 需求 *(必填)*

### 功能需求

- **FR-001**: 扩展必须能够检测用户打开的YouTube视频页面，并识别是否有英文字幕可用
- **FR-002**: 扩展必须能够自动获取视频的完整字幕内容（包括时间轴信息）
- **FR-003**: 扩展必须根据用户预设的英语水平，识别字幕中用户不认识的英文单词
- **FR-004**: 扩展必须调用LLM API，为识别出的生词基于字幕上下文提供简短而合理的中文解释，而非简单的词典翻译
- **FR-005**: 扩展必须在YouTube原生字幕显示区域叠加增强后的混合字幕（原英文 + 中文标注）
- **FR-006**: 扩展必须保持字幕与视频的同步显示，不能有明显延迟（延迟<200ms）
- **FR-007**: 扩展必须提供设置界面，允许用户配置LLM API（API密钥、服务提供商）和选择英语水平（初级/中级/高级）
- **FR-008**: 扩展必须使用chrome.storage.local持久化用户的配置（英语水平、LLM API密钥、词汇表）
- **FR-009**: 扩展必须支持用户手动管理"已掌握词汇表"和"重点关注词汇表"
- **FR-010**: 扩展必须在首次安装后引导用户完成初始设置（LLM API配置和英语水平选择）
- **FR-011**: 扩展必须支持词形智能识别，当用户将某个词标记为熟词时，该词的所有变形（ing、ed、复数、不规则变化等）也被视为熟词
- **FR-012**: 扩展必须在视频暂停时，在每个带中文解释的生词右上角显示小叉图标，用户点击后将该词添加到熟词表并立即移除当前字幕中的中文解释
- **FR-013**: 扩展必须提供词汇导出功能，将已掌握词汇表和重点关注词汇表导出为CSV格式文件，包含词汇类型（已掌握/重点关注）、单词、添加时间等信息
- **FR-014**: 扩展必须提供词汇导入功能，允许用户上传CSV格式文件，导入后覆盖现有的词汇表，并验证CSV格式的正确性
- **FR-015**: 扩展必须在导入词汇前显示确认对话框，明确告知用户导入操作将覆盖现有数据，并显示即将导入的词汇数量

**Chrome扩展特定需求**:

- **FR-016**: 必须使用Manifest V3规范构建扩展
- **FR-017**: 必须使用Service Worker作为后台脚本处理字幕数据和LLM API调用
- **FR-018**: content scripts必须只在youtube.com域名下注入，避免对其他网站的性能影响
- **FR-019**: 必须最小化权限请求，仅请求storage、activeTab和host_permissions（youtube.com）
- **FR-020**: 所有Chrome API调用必须包含错误处理和用户友好的错误提示
- **FR-021**: 字幕数据和LLM翻译结果必须缓存在本地，避免重复请求
- **FR-022**: 必须遵循YouTube的服务条款，不得干扰广告显示或网站核心功能

### 非功能需求

- **NFR-001**: 字幕增强处理必须在视频加载后3秒内完成并开始显示
- **NFR-002**: 插件内存占用必须控制在50MB以内
- **NFR-003**: 翻译标注的字体大小、颜色必须可读，与背景有足够对比度
- **NFR-004**: 扩展必须支持Chrome 88及以上版本
- **NFR-005**: 用户界面必须支持中文和英文双语
- **NFR-006**: CSV导出文件必须使用UTF-8编码，确保中文字符正确显示
- **NFR-007**: CSV导入处理必须在2秒内完成（针对1000个单词以内的文件）

### 关键实体

- **用户配置(UserProfile)**: 存储用户的英语水平设置、LLM API配置、已掌握词汇列表、重点关注词汇列表。关键属性包括englishLevel（初级/中级/高级）、llmApiKey（API密钥）、llmProvider（服务提供商，如OpenAI/Claude）、masteredWords（数组，每个元素包含word和addedTime）、focusWords（数组，每个元素包含word和addedTime）
- **字幕片段(SubtitleSegment)**: 代表视频字幕中的一个时间段片段。关键属性包括startTime（开始时间戳）、endTime（结束时间戳）、originalText（原始英文文本）、enhancedText（增强后的HTML文本，包含翻译标注）
- **单词条目(WordEntry)**: 代表一个需要解释的英文单词。关键属性包括word（单词原形）、contextualExplanation（LLM基于上下文生成的简短中文解释）、difficultyLevel（难度级别）、lemma（词根，用于词形识别）
- **视频会话(VideoSession)**: 代表用户当前观看的视频及其字幕状态。关键属性包括videoId（YouTube视频ID）、subtitleLanguage（字幕语言）、processedSegments（已处理的字幕片段缓存）、lastUpdateTime（最后更新时间）

### 假设

- 假设大多数用户观看的YouTube视频都有英文字幕（官方或自动生成）
- 假设用户有基本的中文阅读能力，中文解释足以帮助理解
- 假设"初级"水平对应3000词汇量，"中级"对应6000词汇量，"高级"对应10000+词汇量
- 假设用户主要在桌面Chrome浏览器上使用（不考虑移动端）
- 假设用户已经拥有或愿意注册LLM API服务（如OpenAI、Claude等）
- 假设用户接受LLM API调用的成本（每次请求可能产生小额费用）
- 假设YouTube的字幕API格式保持稳定，不会频繁变更
- 假设用户网络环境稳定，允许调用外部LLM API
- 假设存在可靠的英语词形还原库（lemmatization）用于词形识别
- 假设用户了解CSV文件格式，或能够使用Excel/Google Sheets等工具编辑CSV文件
- 假设用户的词汇表通常不超过10000个单词（满足chrome.storage.local的存储限制）
